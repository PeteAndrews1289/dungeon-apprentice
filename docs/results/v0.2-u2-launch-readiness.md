## Audit findings retained

The final review found and corrected eight operational integrity risks before protected access:

1. completed PPO updates between exams were not immediately durable;
2. the sequential launcher had no strict resume entry point;
3. a stale first-pass candidate could survive a broken mastery streak;
4. signals or guard failures could leave cohort state labeled `training`;
5. a stale ordinary directory could masquerade as the T7 mount;
6. storage checks could admit a write that crossed a cap;
7. the dashboard omitted preregistered provenance and learning telemetry; and
8. failures after child-directory creation but before callback setup could leave no terminal record.

The fixes do not alter the policy observation, action space, reward, lesson geometry, seed suites,
optimizer, evaluation cases, gates, practice ratios, recovery rules, or action ceilings. They make
the declared experiment resumable and auditable:

- every completed 2,048-action optimizer phase atomically replaces one `latest-safe` bundle;
- interrupted work resumes in a new immutable segment from the highest authenticated safe boundary;
- the active U2 mastery candidate must be the immediately preceding passing exam;
- source, mount, parent, qualification, storage, and process guards fail closed;
- checkpoint publication is staged, size-admitted, post-audited, and rolled back on cap failure;
- setup and training failures produce durable status/crash evidence and close environments; and
- the dashboard exposes a read-only whitelist with freshness, exact provenance, learning counters,
  allocation/recovery state, optimizer metrics, and behavioral diagnostics.

## Qualification boundary

The qualifier owns one canonical directory and one attempt. It accepts only a fresh 256-bit launch
token and the exact acknowledgement phrase; it has no seed, count, output, or rerun override. A
passed report is bound to its source commit, exact bytes, attempt, claim, and generator profile by
the annotated Git tag `u2-preflight-v0.2-u2-20260723` on the frozen GitHub origin.

Training re-verifies the remote tag and every bound field, then uses the exact report snapshot and
validation capability returned by that verification. It does not reread the report to make
curriculum decisions and cannot mint protected access from a user-supplied digest.

The accepted commands and interruption recovery procedure are in the [runbook](../runbook.md). Any
later runtime statement must cite the canonical qualification ledger, tag, cohort manifest, and
child status records.
