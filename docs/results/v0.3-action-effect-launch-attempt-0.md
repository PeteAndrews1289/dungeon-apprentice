## Root cause

The attempt-0 dashboard performed the complete source, tag, qualification, parent, and predecessor
evidence walk on **every** `/api/v03.json` request. That deep authentication took longer than the
launcher's ten-second HTTP client deadline. Each client therefore closed its socket before the
server finished constructing and writing the otherwise valid payload. The dashboard log contains
three resulting `BrokenPipeError: [Errno 32] Broken pipe` traces.

The launcher correctly refused to proceed without an authenticated dashboard response. Because it
exited after cohort creation but before an active arm existed, its `EXIT`/signal trap used the
manifest's legal pending-arm transition to make the root durably terminal: it wrote `arm_started`
and `arm_crashed` for `sham`, with exit code `130`. Those two events are synthetic operational
closeout records. They do **not** mean that a sham trainer started or selected a policy action.

## r1 correction

r1 preserves the model, observations, parent and Adam transplant, reward, PPO, curriculum, seeds,
worker streams, action budgets, exams, history guards, selection rule, storage caps, arm order, and
non-resume rule. It changes only the operational boundary:

- the dashboard process performs the expensive full source/tag/qualification/predecessor
  authentication once at startup, before binding its listening socket;
- every live poll still rereads current cohort, arm, status, frame, and exam evidence;
- every poll rehashes the immutable cohort contract, qualification report, and qualification
  checksum so byte tampering still fails closed;
- the bounded per-poll work now completes inside the launcher's health deadline, avoiding the
  startup disconnect loop; and
- the launcher authenticates expected identity fields in the API payload. The API does not invent
  or require a literal `healthy: true` field.
