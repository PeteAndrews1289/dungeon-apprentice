Stage-A r1 successfully froze, qualified, opened its read-only dashboard, transplanted the
confirmed U1 policy, verified the first matched sham rollout, and began training. The launcher then
misclassified its trainer supervisor as a second neural trainer. A second shell-control defect
prevented the launcher's intended exit cleanup from running automatically. The sham worker

This is a real partial training record, unlike the zero-action attempt-0 failure, but it still
cannot answer the scientific question. A two-arm matched study with only part of its first arm is
not a comparison. The sham's initial, first-exam, and latest-observed checkpoints are
non-promotable evidence and may never be resumed or reused.

The separately versioned replacement is the prospective
[v0.3 Stage-A r2 protocol](../protocol-v0.3-action-effect-architecture-r2.md). It preserves every
scientific variable, assigns fresh identities, restarts **both** arms from confirmed U1, and changes
only the process-classification and explicit-cleanup boundary.

## Root cause

### 1. Whole-command-line process matching

The r1 launcher counted trainers with `pgrep -f`. The actual trainer command contains
`python -m dungeon_apprentice.v03_action_effect_train`. The supervisor's command line also contains
that complete child command after its `--` separator:

```text
u2_trainer_supervisor.py -- python -m dungeon_apprentice.v03_action_effect_train ...
```

Searching the whole command line therefore classified both PIDs as neural trainers even though
only the child process was a trainer. The launcher correctly expected exactly one trainer but
received a false count of two and emitted its final error line.

### 2. Implicit `errexit` did not run cleanup

The failed cardinality assertion returned from a shell function while zsh `set -e` was active.
That function-return error path exited orchestration without executing the intended `EXIT` cleanup
trap. The supervisor, trainer, sleep-prevention process, and dashboard were therefore not stopped
or terminalized by the original failure path. Their continued records between `04:56:53` and
`05:02:56` prove that cleanup did not run then.

An explicit later stop caused the supervisor to forward `SIGTERM`; its evidence reports worker exit
status `-15`. The manifest subsequently records the arm-level launcher failure as exit code `1`.
The trainer's final status necessarily remains `phase: training`, and no formal terminal report or
`process-closeout.json` exists.

The post-incident read-only inventory found no remaining launcher, supervisor, trainer,
`caffeinate`, or dashboard process and no listener on port `8789`. That later observation confirms
cleanup, but it is not a substitute for the missing launcher-sealed process-closeout artifact.
